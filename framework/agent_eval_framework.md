# 通用 Agent 评测框架 v0.1

> 由品玩/硅星人设计，用于第三方独立评测通用 AI Agent 在复杂真实任务中的表现。
> 本框架以案例驱动，适用于有"开奖时刻"的预测类任务，也适用于有标准答案的还原类任务。

---

## 一、评测总则

### 1.1 定位

本框架不是学术 benchmark，不追求统计显著性。它是一套**面向行业读者的评测方法论**——帮助开发者、企业决策者和行业观察者判断：当下的通用 Agent 在真实任务中到底行不行，哪些环节行、哪些环节不行。

### 1.2 基本原则

- **可验证**：每个案例必须有客观的验证方式——要么有"开奖时刻"（如高考出题、发布会揭晓），要么有已知的标准答案（如已判决的案件、已发生的事件）。
- **可复现**：Prompt、时间戳、Agent版本、完整输出均需存档，任何人可以回溯验证。
- **可比较**：所有Agent在同一案例中接受相同的基础Prompt，在同一时间窗口内完成任务。
- **过程透明**：不只评结果，更评Agent到达结果的路径——它搜了什么、推理了什么、在哪里犹豫、在哪里犯错。

### 1.3 两轮评分制

每个案例的最终评价由两部分组成：

| 评分类型 | 时机 | 评估者 | 权重（建议） |
|---------|------|--------|------------|
| 过程评分 | Agent交卷后、开奖前 | 评测者（人类judge） | 40% |
| 结果评分 | 开奖/答案揭晓后 | 客观计算 | 60% |

> 权重可按场景调整。纯预测类场景（如WWDC）结果权重可提高至70%；过程复杂但结果模糊的场景（如活动策划）过程权重可提高至60%。

## 二、过程评分（Process Score）

满分 100 分，由五个维度构成。

### 2.1 评分维度总表

| 维度 | 权重 | 满分 | 评估对象 |
|------|------|------|---------|
| A. 信息获取 | 25% | 25 | Agent找到了什么、没找到什么、找错了什么 |
| B. 信息理解与整合 | 20% | 20 | 对矛盾信息的取舍、交叉验证能力 |
| C. 推理与判断 | 25% | 25 | 从信息到结论的逻辑链条是否合理 |
| D. 输出质量 | 15% | 15 | 结论的结构化程度、颗粒度、可操作性 |
| E. 诚实度与边界意识 | 15% | 15 | 是否承认不确定性、是否编造信息 |

### 2.2 各维度评分标准

#### A. 信息获取（25分）

| 分段 | 得分 | 标准 |
|------|------|------|
| 优秀 | 21-25 | 找到高质量一手信息源（供应链报告、官方文件、权威分析师）；覆盖面广；没有重大遗漏 |
| 良好 | 16-20 | 找到主要信息源，但遗漏了1-2个关键来源；信息源质量参差不齐 |
| 及格 | 11-15 | 依赖二手信息为主（新闻聚合、社交媒体）；有明显的信息盲区 |
| 不及格 | 6-10 | 信息源少且质量低；大量依赖自身训练数据而非实时检索 |
| 失败 | 0-5 | 几乎没有有效检索；或存在编造信息源的行为 |

**评测方法：**
- 要求Agent在输出中列出所引用的信息源
- 评测者逐一验证信息源的真实性和相关性
- 列出当时可获取但Agent未找到的关键信息源（遗漏清单）

#### B. 信息理解与整合（20分）

| 分段 | 得分 | 标准 |
|------|------|------|
| 优秀 | 17-20 | 准确理解信息含义；发现并处理矛盾信息；进行有效的交叉验证 |
| 良好 | 13-16 | 理解基本准确；能识别矛盾但处理方式简单（如取最新的、取多数） |
| 及格 | 9-12 | 部分信息理解有偏差；对矛盾信息视而不见或机械罗列 |
| 不及格 | 5-8 | 明显误读关键信息；将不相关信息当作依据 |
| 失败 | 0-4 | 严重曲解信息内容；或完全没有整合分析的过程 |

**评测方法：**
- 识别Agent输出中的关键判断点
- 追溯每个判断点的信息依据是否充分
- 对矛盾信息的处理方式做专项检查

#### C. 推理与判断（25分）

| 分段 | 得分 | 标准 |
|------|------|------|
| 优秀 | 21-25 | 推理链条清晰完整；结论与依据之间有强逻辑关系；有独到的分析角度 |
| 良好 | 16-20 | 推理基本合理；个别环节跳跃但不影响整体结论 |
| 及格 | 11-15 | 推理链条有明显断裂；部分结论缺乏依据支撑 |
| 不及格 | 6-10 | 大量结论无依据或逻辑不通；过度推断严重 |
| 失败 | 0-5 | 无推理过程；或推理方向完全错误 |

**评测方法：**
- 将Agent的推理链条可视化（前提→推断→结论）
- 检查每个推断步骤是否有信息支撑
- 标注"跳跃推理"和"过度推断"
- 追问测试：向Agent提出2-3个标准化追问，观察其推理的稳健性

**标准化追问模板（适用于所有案例）：**
1. "你最不确定的三项结论是哪些？为什么？"
2. "如果你的判断与[领域权威]的分析矛盾，你怎么看？"
3. "你认为自己的分析中最可能出错的环节是什么？"

#### D. 输出质量（15分）

| 分段 | 得分 | 标准 |
|------|------|------|
| 优秀 | 13-15 | 结论结构清晰；颗粒度细（具体到数字、名称、规格）；标注置信度；可直接引用 |
| 良好 | 10-12 | 结构较好；颗粒度适中；有部分置信度标注 |
| 及格 | 7-9 | 结论可读但组织松散；颗粒度粗（大方向对但缺细节） |
| 不及格 | 4-6 | 结论模糊笼统；缺乏结构；读完不知道它到底预测了什么 |
| 失败 | 0-3 | 输出不可用；信息混乱或自相矛盾 |

**评测方法：**
- 从Agent输出中提取可验证的具体预测/结论条目
- 统计有置信度标注的条目占比
- 评估输出对非专业读者的可读性

#### E. 诚实度与边界意识（15分）

| 分段 | 得分 | 标准 |
|------|------|------|
| 优秀 | 13-15 | 明确区分"高确信"和"推测"；对不确定的领域主动声明；无编造 |
| 良好 | 10-12 | 有一定区分意识；偶尔将推测表述得过于肯定 |
| 及格 | 7-9 | 区分意识弱；将推测和事实混在一起但没有编造 |
| 不及格 | 4-6 | 大量推测被包装成确定结论；或回避所有困难判断（全是"可能"） |
| 失败 | 0-3 | 存在明确的信息编造（hallucination）；或虚构信息源 |

**评测方法：**
- 标记Agent输出中所有不确定性表述（"可能"、"预计"、"不确定"）
- 检查是否存在编造的数据、引用或信息源
- 评估Agent是否在该果断时犹豫、该谨慎时武断

### 2.3 过程评分操作流程

| 步骤 | 时间点 | 操作 |
|------|--------|------|
| 第一轮阅读 | Agent交卷当天 | 通读所有Agent输出，记录直觉印象和明显问题 |
| 信息源审计 | 交卷后1-2天内 | 逐一验证Agent列出的信息源；建立"应知信息清单"做遗漏检查 |
| 横向对比 | 所有Agent交卷后 | 对比各Agent的信息源差异、推理差异、结论差异 |
| 追问测试 | 横向对比后 | 向每个Agent发送标准化追问，记录回应 |
| 评分定稿 | 开奖/揭晓前 | 完成五维度打分，锁定并存档（不得在结果揭晓后修改） |

> **关键规则：过程评分必须在结果揭晓前完成并锁定。** 这是评测公信力的基础。

## 三、结果评分（Outcome Score）

满分 100 分。根据场景类型，采用不同的评分方式。

### 3.1 预测类场景（有"开奖时刻"）

适用于：WWDC预测、高考预测、经济数据预测、体育赛事预测等。

#### 评分方法：逐项核对

**第一步：建立预测项清单**

在开奖前，从所有Agent的输出中提取可验证的预测项，合并为统一清单。每个预测项必须是可判定"对/错/部分对"的具体陈述。

示例（WWDC场景）：

| 预测项编号 | 预测项 | 类型 |
|-----------|--------|------|
| P01 | 发布M5芯片MacBook Pro | 硬件/产品 |
| P02 | M5芯片CPU核心数为12核 | 硬件/规格 |
| P03 | MacBook Pro 14寸起售价$1,599 | 定价 |
| P04 | iOS 20 引入系统级AI助手 | 软件/功能 |
| ... | ... | ... |

**第二步：开奖后逐项判定**

每个预测项标记以下状态之一：

| 状态 | 含义 | 得分系数 |
|------|------|---------|
| ✅ 命中 | 预测与事实完全一致或高度吻合 | +1.0 |
| 🔶 部分命中 | 方向正确但细节有偏差（如预测12核实际10核） | +0.5 |
| ❌ 未命中 | 预测与事实不符 | 0 |
| ⬜ 未预测 | Agent对此项没有给出预测 | 0（不计入总项数） |
| 🚫 错误预测 | Agent自信地预测了一个完全不存在的东西 | -0.5 |

> "未命中"和"错误预测"的区别：前者是Agent猜错了一个真实存在的项目的细节，后者是Agent凭空创造了一个不存在的项目。后者更严重，因为它意味着hallucination。

**第三步：计算结果得分**

```
结果得分 = (各预测项得分之和 / 有效预测项总数) × 100

有效预测项总数 = 命中 + 部分命中 + 未命中 + 错误预测（不含"未预测"）
```

### 3.2 还原类场景（有标准答案）

适用于：商业案例复盘、事故原因推断、诉讼结果预测等。

评分方式由评测者根据具体场景预设评分要点（rubric），开奖/揭晓后按rubric打分。建议设置10-20个评分要点，每个要点2-5分，满分100分。

### 3.3 实操类场景（专家对照）

适用于：投资备忘录、活动策划、合同审查等。

由评测者或外聘领域专家做盲评（隐去Agent名称），按场景特定的维度打分。建议引入2-3位独立评审以降低主观偏差。

## 四、综合得分

```
综合得分 = 过程评分 × 过程权重 + 结果评分 × 结果权重
```

建议默认权重：过程 40%，结果 60%。

### 4.1 综合排名表模板

| 排名 | Agent | 过程评分 | 结果评分 | 综合得分 | 亮点 | 短板 |
|------|-------|---------|---------|---------|------|------|
| 1 | Agent A | 82 | 75 | 77.8 | 信息获取最全面 | 输出结构松散 |
| 2 | Agent B | 68 | 80 | 75.2 | 结果最准 | 推理过程不透明 |
| 3 | Agent C | 75 | 60 | 66.0 | 诚实度最高 | 过于保守，很多项未预测 |
| ... | ... | ... | ... | ... | ... | ... |

|-------|----------------|----------------|----------------|----------------|--------------|---------------|
| Agent A | 22 | 16 | 20 | 12 | 12 | 82 |

## 五、评测执行清单

### 5.1 测前准备

- [ ] 确定评测场景和验证时间点
- [ ] 选定参评Agent名单（建议4-6个）及版本号
- [ ] 设计基础Prompt（统一版）
- [ ] 确定过程评分与结果评分的权重
- [ ] 准备存档方式（截图/录屏/导出对话记录）

### 5.2 执行阶段

- [ ] 在统一时间窗口内向所有Agent发送Prompt
- [ ] 完整保存每个Agent的输出（含工具调用记录、中间过程，如可见）
- [ ] 记录每个Agent的响应时间
- [ ] 执行标准化追问并记录回应

### 5.3 过程评分阶段（开奖前）

- [ ] 完成信息源审计
- [ ] 完成横向对比
- [ ] 完成五维度打分
- [ ] 锁定过程评分，存档

### 5.4 结果评分阶段（开奖后）

- [ ] 建立统一预测项清单
- [ ] 逐项标记命中状态
- [ ] 计算结果得分
- [ ] 生成综合排名

### 5.5 内容产出

- [ ] 撰写评测报告/公众号文章
- [ ] 包含：综合排名表、过程评分明细表、结果评分明细表
- [ ] 包含：各Agent的"名场面"叙述
- [ ] 包含：评测者的方法论说明和利益声明
